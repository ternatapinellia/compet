=== projects/openqq-bridge/index.html
   OpenQQ Bridge
   ☀️
   ← 返回首页
   OpenQQ Bridge
   项目简介
   OpenQQ Bridge 是用于 SeaDice 与 OpenQQ 身份兼容的数据桥接工具。
   用于解决 OpenQQ 平台身份变化后，
   原有角色卡、属性数据以及日志数据无法直接读取的问题。
   支持旧 QQ 数据绑定到当前 OpenQQ 身份，
   实现数据兼容读取。
   本版支持：
   多 SeaDice 实例分别配置 Bridge 端口。
   在 SeaDice 插件配置页面填写发件邮箱、SMTP 授权码、SMTP 服务器和端口。
   .旧QQ邮箱测试：向配置中的发件邮箱发送测试邮件。
   .旧QQ绑定
   ：自动向
   @qq.com 发送 6 位验证码。
   .旧QQ验证码
   ：验证成功后才执行数据迁移。 验证码 5 分钟有效，最多错误 5 次。
   .旧QQ+旧群已绑定其他 OpenQQ 身份时拒绝再次绑定。
   使用方式：
   双击启动openqq.exe，然后保持运行，不能关闭
   在目标QQ 群执行：
   如  .旧QQ绑定 2522629086 1081354778，也就是格式是： .旧QQ绑定
   ，后bot会朝你使用账号的QQ号@qq.com发送验证码邮件，输入。旧QQ验证码+6位数字的验证码后可绑定。再次绑定该群号和QQ账号会失败，仅限单次数绑定。QQ号+群号可用于多群进行绑定查询log。
   绑定完成后再执行：
   .st或者。pc或者。log，先前的log可通过log get+名字取出。
   下载
   直接下载
   Github Release
   百度云链接
   如果下载后无法打开，
   或者打开后立即关闭，
   请检查 Windows 安全中心和防火墙是否允许该软件运行。
   大概率是被防火墙拦截。
   注意：
   - 插件配置中的“SMTP授权码”不是邮箱登录密码。
   - QQ邮箱通常使用 smtp.qq.com:465，并使用 SMTP 授权码。
   - 测试邮件会发送到你填写的“发件邮箱”本身。
   - bridge_port.txt 与 EXE 放在同步桥目录中；EXE 默认读取其中的端口。
   - email_config.json 仅作为兼容/手工启动备用配置，本版正常使用时由 SeaDice 插件配置向 Bridge 临时下发邮箱配置。
   不要在干净备份上直接测试 .st；干净备份里的角色仍属于旧 QQ，OpenQQ 官 bot 不会自动显示它。
   TIPS：因为文件只读取海豹的data和datalog的db文件，所以有的角色卡可能会在转换以后出现丢失情况，比如出现空角色卡，或者log绑定失败，大部分是因为数据库出现了问题，可用原始备份的data和datalog的db文件进行替换再删除相应的后缀为wal和shm的文件，海豹再度启动会自动生成相应的wal和shm干净文件。data文件会在数据转换前进行备份，后缀是beforexxxx
   如十分必要可以来找骰主尝试找回数据。把data和datalog整理读取后可以得到对应的角色卡文件，只要存在过。
   这版插件是AI写的代码，不能保证不会出现其他的bug，除此以外，尚未验证过该插件同步的log数据是否能继续记录日志。

=== projects/openqq-plugin/index.html
   OpenQQ Plugin
   ☀️
   ← 返回首页
   OpenQQ Plugin
   项目简介
   本工具用于为开放平台机器人后台回调提供稳定的 Webhook 地址。
   通过 Caddy 提供 HTTPS 反向代理，
   配合 FRP 内网穿透，
   解决本地服务器无法直接提供公网 HTTPS 回调地址的问题。
   使用场景
   适用于：
   没有公网 IP 的机器人服务器
   本地运行机器人程序，需要公网 Webhook 地址
   不希望购买国内备案域名的用户
   需要长期稳定回调地址的开放平台机器人
   下载
   直接下载
   Github Release
   百度云链接
   部署方式
   方案 A：拥有国内域名
   如果拥有已经备案的国内域名，
   可以直接部署。
   下载工具包后：
   修改 Caddyfile
   修改 config/bots 文件
   填写机器人 AppID 和 Secret
   启动服务即可
   其中 bots 文件需要填写开放平台机器人的身份信息。
   Caddyfile 用于配置 HTTPS 域名以及反向代理规则。
   方案 B：没有国内域名
   可以租用国外云服务器。
   推荐：
   日本节点 VPS（延迟较低）
   Linux 系统
   安装 Caddy + FRP
   服务器端负责：
   绑定公网域名
   提供 HTTPS
   转发 Webhook 请求
   本地服务器负责：
   运行机器人程序
   运行 frpc
   保持与 VPS 的连接
   Linux 部署流程
   1. 更新系统
   sudo apt update
   sudo apt upgrade -y
   2. 安装基础工具
   sudo apt install wget curl unzip nano -y
   3. 安装 Caddy
   sudo apt install caddy -y
   4. 编辑 Caddy 配置
   sudo nano /etc/caddy/Caddyfile
   示例：
   your-domain.com {
   reverse_proxy 127.0.0.1:19093
   }
   保存：
   Ctrl + O
   Enter
   Ctrl + X
   重载：
   sudo systemctl reload caddy
   5. 安装 FRP
   下载对应 Linux 架构版本：
   uname -a
   解压：
   tar -zxvf frp.tar.gz
   进入目录：
   cd frp
   启动：
   ./frpc -c frpc.ini
   FRP 支持将内网服务通过公网服务器转发出去，常用于没有公网 IP 的场景。:contentReference[oaicite:2]{index=2}
   配置文件修改
   config/bots
   修改：
   appid=你的机器人appid
   secret=你的机器人secret
   替换成开放平台提供的信息。
   Caddyfile
   修改域名：
   your-domain.com
   修改代理端口：
   127.0.0.1:你的监听端口
   frpc.ini
   示例：
   [common]
   server_addr = VPS地址
   server_port = 7000
   [openqq]
   type = http
   local_ip = 127.0.0.1
   local_port = 你的机器人端口
   custom_domains = your-domain.com
   启动检查
   查看 Caddy：
   systemctl status caddy
   查看 FRP：
   ps aux | grep frpc

   项目简介
   Windows桌面打字&手柄识别工具，含三角符文各种角色皮肤
   工具是x发布的compet的补丁包，compet原软件链接：https://github.com/morningmeal/morningmeal_ComPet
   该补丁包支持手柄识别以及游戏时候的按键和手柄识别，理论上其他打字桌宠可通用（如果是py代码版本的）
   使用说明
   gamepad-package.exe解压后文件夹中数十个文件需要放置到和桌宠软件exe同目录下。该补丁针对软件名，只能使用compet.exe该软件名。
   使用的时候请首先按下gamepadsetting.bat来配置手柄按键，目前按键键位按照xbox手柄键位书写。而后按下start.vbs进行启动。
   ggdw为swapspamton的皮肤包。addispam为ads时期spamton的皮肤包，dnt为defernull tenna的皮肤包，big shot是dr的bs时期皮肤包。
   解压后即可导入图片使用，如软件支持zip导入，也可直接导入。
   config.json中可以查看各个桌宠的按键配置规范，f18-f24和上下左右按键等为原本配置的手柄键位。
   不支持开机自启，需要自启请自行将start.vbs添加到开机自启的注册表中。
